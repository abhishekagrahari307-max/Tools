What runs where

Nothing here is a placeholder: every tile opens a working tool. The engines differ, so this table is honest about it.

Pure on-device DSP

Trim, merge, mix, split, fade, pitch, speed, EQ, compressor, normalizer, noise reduction, vocal removal, stereo, silence finder, BPM, reverse, ringtone, podcast, waveform and spectrum: Web Audio sample maths, no codec involved. These export WAV directly and MP3 through the bundled LAME encoder.

Canvas + MediaRecorder

Quick edits — trim, merge, crop, resize, speed, filters, slideshow, meme — draw each frame to a canvas and record it. Chrome and Edge emit MP4, Firefox emits WebM. This path runs in real time, so a 2-minute clip takes about 2 minutes.

FFmpeg in WebAssembly

Four tools use a self-hosted FFmpeg 5.1.4 build (x264, x265, vpx, aac, lame, opus, libass): Video Compressor, Colour & Stabilise, Subtitle Editor and GIF Maker Pro. It decodes frame by frame — usually faster than real time — and needs a one-off 31 MB engine load from this folder, never a CDN.

WebAssembly engines

Pixora's PDF tools run on PDF-Lib plus qpdf compiled to WebAssembly, OCR on a bundled Tesseract build with English and Hindi models, and Word export builds the DOCX file in the browser. These files load the first time you open such a tool.

Browser speech APIs

Text-to-speech and speech-to-text use the browser's own speechSynthesis and SpeechRecognition. Chrome and Edge support both; Firefox currently ships neither, and the tool says so instead of failing silently.

Why nothing gets uploaded

On-device processing

Audio is decoded with the Web Audio API, video frames are drawn to a canvas, PDFs are edited with PDF-Lib and qpdf compiled to WebAssembly, and OCR runs on a bundled Tesseract build. Your bytes stay in this tab.

No CDN, no tracking

Every library is served from this folder. There is no analytics, no account, no cookie wall and no third-party request while you work — the pages keep working once loaded, even offline.

Heavy engines load on demand

The OCR models, PDF engines and Hindi font live in pixora/engines/ and are fetched only when you open a tool that needs them, so the studio opens in seconds instead of carrying 11 MB everywhere.

Good to know

  • Serve these pages over http(s) (GitHub Pages does this). Opening the HTML straight from disk blocks the on-demand engine files.
  • Video previews use your browser's codecs; the FFmpeg tools add a 31 MB one-off engine download, after which it is cached and works offline.
  • Nothing is permanent: reloading clears the workspace, so download finished files before you close the tab.
